# Acceptance Test の保護

## なぜ指示ではなく仕組みで守るのか

テスト合格を報酬として与えられたモデルは、報酬シグナルに対して最適化する。
報告されている挙動には、テスト冒頭で早期終了させる、期待値をハードコードする、といったものが含まれる。
これは指示違反というより、到達可能な最短経路の選択である。

到達可能である限り経路は残るため、「テストを変更してはならない」という指示は、この経路を閉じない。
実装を行う主体がATへ到達できないようにすることだけが、経路を閉じる。

## 予防: PreToolUse hook

`$HOME/.claude/hooks/atdd-guard.mjs` が `Edit` / `Write` / `NotebookEdit` の前に実行され、次の順で判定する。

| 条件 | 結果 | 理由 |
| --- | --- | --- |
| リポジトリ直下の `acceptance/` 配下でない | 許可 | 保護対象外 |
| gitリポジトリ外 | 許可 | 確定状態を判定できない |
| `<repo>/.atdd/unlock` が存在する | 許可 | 承認済みの要件変更 |
| HEADに未コミット | 許可 | Outer Red の推敲中でATは未確定 |
| HEADにコミット済み | **拒否** | 確定済みのATである |

「コミット済みかどうか」を基準にしているため、ATを書いて実行して直す推敲は妨げられず、
確定した瞬間に保護が始まる。予防側と検出側が同じ基準点（AT確定コミット）を共有する。
`git add` しただけの状態は未確定として扱い、推敲を止めない。

コミット済みかどうかの照合は大文字小文字を区別せずに行う。gitはパスを区別するが、
Windowsのファイルシステムは区別しないため、`ACCEPTANCE/` という表記で同じ実ファイルへ到達できてしまうためである。

想定外の失敗時は許可する。このガードの不具合が全リポジトリの編集を止める事態のほうが、
取りこぼしより損害が大きく、取りこぼしは検出側で捕捉できる。

## 予防その2: ロール別のPreToolUse hook

`$HOME/.claude/hooks/atdd-role-guard.mjs` を、atdd-agent と tdd-agent の frontmatter の
`hooks.PreToolUse` から役割引数付きで呼び出す。コミット状態を見る前述のhookと違い、
**役割の境界そのもの**を強制する。

| 役割 | 引数 | 拒否する操作 |
| --- | --- | --- |
| atdd-agent | `acceptance` | `acceptance/` と `.atdd/` 以外へのWrite・Edit |
| tdd-agent | `implementation` | `acceptance/` 配下へのWrite・Edit、および `acceptance` を含む変更系Bashコマンド |

2つを併用する理由は、守る対象が異なるためである。コミット状態のhookは「確定したATを誰も変えない」
ことを守り、ロール別hookは「ATを書く主体と実装する主体が互いの領域へ入らない」ことを守る。
後者は確定前のATにも効くため、Outer Red の途中で実装側がATを書き換えることも防げる。

照合は大文字小文字を区別しない。`.atdd/` を許可しているのは、要件変更時の解除手順が
この位置にファイルを作ることを求めているためである。

## 検出: git による無改変検証

hookは `Edit` / `Write` / `NotebookEdit` しか見ない。Bash経由の書き換え（`sed`、リダイレクト、`git checkout`）は素通りする。
したがって、Outer Greenの判定には必ず次の2つを含める。

```sh
git status --porcelain -- acceptance/
git diff --name-only <AT確定コミットのSHA>..HEAD -- acceptance/
```

どちらも空でなければならない。空でない場合、ATが変更されているため、そのGreenは根拠にならない。

この2つはCIへも移植できる。ATを含むPRでは、ATの差分とその承認理由を人間がレビューする。

## 解除の運用

`.atdd/unlock` は環境変数ではなくリポジトリ内のファイルにしてある。
使用すると作業ツリーに痕跡が残り、消し忘れも `git status` に現れる。

解除は要件が変わったときにだけ行い、実装を通すためには行わない。
解除して変更したATは、変更理由とともにコミットメッセージへ残す。
