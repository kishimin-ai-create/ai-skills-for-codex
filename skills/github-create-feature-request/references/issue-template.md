# 機能要望Issue本文

リポジトリ固有の機能要望テンプレートがない場合に使う。

```markdown
## 解決したい課題

<誰が、どの状況で、何に困っているか>

## 提案する解決策

<期待する利用者体験または開発者体験。実装方法は必要な場合だけ書く>

## 代替案

<検討した別案と採用しない理由。未検討なら「未検討」>

## 受入条件

- [ ] <観測可能な完了条件>

## 対象外

- <このIssueに含めない範囲。なければ「なし」>

## 補足

<関連Issue、ADR、画面、制約。なければ「なし」>
```

## 記入規則

- 解決策より先に課題を書く。
- 優先度、利用者数、効果を根拠なしで作らない。
- 受入条件を実装ファイルではなく外部から観測できる結果で書く。
- 代替案が未検討なら、もっともらしい案を創作しない。
