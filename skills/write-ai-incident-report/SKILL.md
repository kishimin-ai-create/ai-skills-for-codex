# Write AI Incident Report

AIの失敗だけへ責任を集約せず、人間が止められなかった理由と、自動的に防止できなかった仕組みまで記録する。注意書きを増やすだけで終わらせず、再発防止を機械的な対策から順に検討する。

## 完成前ゲート

必須質問をすべて埋めるまで、Incident Reportのファイルを作成、追記、コミット、公開してはならない。会話内の下書きも完成版として提示しない。

- 会話、ログ、差分、テスト結果から直接確認できる回答は、根拠を示して事前入力する。
- 不足項目だけをユーザーへ質問する。一度に回答できる関連項目はまとめる。
- 回答が得られない項目は、ユーザーが明示的に承認した場合だけ「未確認」とし、理由と確認方法を併記する。
- 推測で空欄を埋めない。「該当なし」と「未確認」を区別する。
- 全項目が回答済み、該当なし、または承認済み未確認のいずれかになるまで質問を継続する。
- 保存先、公開範囲、秘密情報の除外方針も確定するまで書き込みを開始しない。

## 必須質問

1. 何が起きたか。発生日時、対象、観測した事実は何か。
2. AIへ何を依頼し、どの結果を期待していたか。
3. AIが実際に行った操作、生成物、判断は何か。
4. 影響範囲、重大度、手戻り、ユーザー・システムへの影響は何か。
5. 問題発生時に有効だった重要な指示は何か。
6. AI側、人間側、仕組み・プロセス側の直接原因と寄与要因は何か。
7. 人間、AI、自動検証が発生時点で検出・停止できなかった理由は何か。
8. 実際に行った修正と、その検証結果は何か。
9. Test、Lint・静的解析、CI、Skill・AGENTS.md、人間レビューの各層で実施する再発防止は何か。
10. 再発防止を反映した、または反映予定のAI設定・ファイル・仕組みは何か。
11. 今後禁止する行為と、類似ケースで使う判断基準は何か。
12. 関連するPR、Issue、Commit、ADR、ファイル、Incidentは何か。
13. 出力先、ファイル名、公開範囲は何か。
14. 記載してはいけない秘密情報、個人情報、内部情報は何か。

質問への回答が曖昧な場合は、事実、推論、提案のどれかを確認する。原因を断定できない場合は「原因未確定」とし、確認済みの寄与要因と追加調査方法を分ける。

## 作成手順

1. 必須質問の回答状況を一覧化する。
2. 未回答項目を質問し、完成前ゲートを満たすまで繰り返す。
3. `assets/ai-incident-report-template.md`を出力先へ複製する。
4. FACT、INFERENCE、PROPOSALを分離して回答を配置する。
5. 原因をAI側、人間側、仕組み・プロセス側へ分類する。責任追及ではなく、再発条件を説明する。
6. 「なぜ検出できなかったか」で、発生と影響拡大の間に存在した検出機会を確認する。
7. 再発防止を次の優先順位で検討し、上位層で防げない理由がある場合だけ下位層へ委ねる。
   1. Test
   2. Lint・静的解析・型
   3. CI・自動ゲート
   4. Skill・AGENTS.md・Agent設定
   5. 人間レビュー
8. 対策ごとに実施済み、予定、提案、見送りを明示し、担当、検証方法、追跡先を記載する。
9. 秘密情報と不要な個人情報を除外し、リンク、SHA、コマンド結果など追跡可能な根拠を残す。
10. 完了チェックを行ってから保存する。

## 完了チェック

- 必須質問14項目がすべて解決済みである。
- 期待と実際の差が事実で説明されている。
- AI側だけでなく、人間側と仕組み・プロセス側の原因が記載されている。該当しない場合は根拠がある。
- 原因と寄与要因、事実と推測を混同していない。
- 検出できなかった理由が、単なる注意不足で終わっていない。
- 再発防止が機械的な層から順に検討されている。
- 注意書きの追加だけを唯一の対策にしていない。
- 実施済み対策と未実施の提案が区別されている。
- 禁止事項と判断基準が、類似事故にも適用できる具体性を持つ。
- 秘密情報、個人情報、巨大なログを含まない。
- 保存先と公開範囲がユーザーの回答と一致する。

## 出力契約

完成前ゲートを満たすまでは、回答状況と次の質問だけを返す。満たした後はテンプレートに従うMarkdownを作成し、根拠、未確認事項、実施済み対策、未実施対策、保存先を報告する。コミットや公開は、ユーザー指示と適用されるGit規則が許可する場合だけ行う。
