# Collection Pause and Resume Design

収集を「止める」の意味を、新規ジョブの受付、実行中の処理、保存済み進捗に分けて確定する。設計依頼だけで稼働環境を変更しない。

## 現状と停止範囲

- 対象サイト、収集単位、起動元、キュー、ワーカー、状態保存先を実装と設定から追う。公式サイトとアーカイブなど複数の情報源があれば、停止範囲を別々に扱えるか確認する。
- スケジューラー無効化、情報源の非アクティブ化、新規処理の抑止、実行中ジョブの中断を同じ操作とみなさない。既存の有効・無効設定が担う別の意味を壊さない。
- 操作主体と環境、GUIからAPIへの経路、認証・認可境界を確認する。画面上のボタン制御だけで操作権限を保証しない。

## 決める契約

状態名は現行モデルに合わせる。次の論点を状態遷移表へ落とし、未決の選択は明示する。

| 論点 | 確定する内容 |
| --- | --- |
| 停止の完了 | 要求受理と実際の停止をどう区別し、何を観測できたら停止完了か |
| 実行中の処理 | 完了を待つか中断するか、保存済みデータ・未完了バッチ・外部要求をどう扱うか |
| 次回実行 | 停止中の定期起動、既存キュー、停止直前に受付したジョブをどう扱うか |
| 再開 | 誰が再開し、どのチェックポイント・未取得集合から始めるか |
| 終了時刻不明 | 手動再開、終了時刻、ヘルス確認など何を再開条件とするか。時刻不明から自動再開を推定しない |
| 永続化と競合 | 再起動・複数ワーカーでも停止状態を維持できるか。停止と受付・再開が競合した際の優先順位 |
| 有効化時点 | 実装完了、デプロイ、機能の有効化、実際の停止操作を区別する |

手動操作の多重送信に対する結果、操作結果の表示、失敗時の再試行も契約に含める。再開時に既存データを消したり、全件を無条件に再取得したりする方針を暗黙に採らない。

## 成果物と検証

現状の根拠、状態遷移表、GUI/APIの操作契約、実行境界への影響、未決事項、観測可能な受け入れ条件を提示する。図やテストでは、少なくとも以下の振る舞いを確定仕様と照合する。

- 停止中に新規の外部収集が始まらず、停止直前の受付も仕様どおり処理される。
- 実行中処理の完了・中断と、部分保存・残件が区別できる。
- 同じ停止・再開要求、権限不足、再起動、対象外の情報源の動作が仕様どおりになる。
- 再開後の次回実行が二重起動せず、保存済み進捗を保つ。

実装や稼働操作まで依頼された場合は、その許可範囲で既存の開発・運用手順へ進む。設計の作成を、本番停止や自動再開の有効化の許可として扱わない。
