# Defer Decision

無人で走るループには質問を投げる相手が居ない。止まれば次の起動まで何も進まず、
最終報告に書くだけでは、セッションが終わった時点で質問が消える。

このSkillは、**質問をIssueへ置いて先へ進む**ための手順である。人間は都合のよいときに
返信すればよく、次の起動がそれを読んで再開する。

## 使う前に

**まず `decision-agent` へ尋ねる。** 資料に書かれている事柄をIssueへ質問すると、
人間に既知のことを二度書かせることになる。

| decision-agent の判定 | 次の行動 |
| --- | --- |
| 書かれている | その答えで進む。質問しない |
| 先例のみ | 先例に従って進み、前提として記録する。質問しない |
| 書かれていない | このSkillの手順へ進む |

## 手順

### 1. 未回答の質問が無いか確認する

同じ質問を二度書かない。対象Issueのコメントを取得する。

```sh
gh issue view <番号> --json comments --jq '.comments[] | {createdAt, body}'
```

ループが出した質問は本文に `<!-- loop:needs-decision -->` を含む。

- **最後のコメントがループの質問** → まだ回答が無い。このIssueは飛ばして次へ進む
- **質問より新しい、マーカーの無いコメントがある** → それが回答である。ステップ4へ
- **質問が無い** → ステップ2へ

投稿者では判別しない。ループも人間も同じアカウントで書き込むためである。

### 2. 質問をIssueへ残す

```sh
gh issue comment <番号> --body "$(cat <<'BODY'
## 判断が必要

<!-- loop:needs-decision -->

**決まっていないこと**: <1文>

**なぜ進めないか**: <推測で埋めると何が壊れるか>

**調べた範囲**: <確認した資料と、そこに書かれていなかったこと>

**選択肢**:

- A: <案> — <結果>
- B: <案> — <結果>

このコメントに返信してください。次回の実行が読み取って再開します。
BODY
)"
```

選択肢は、資料から読み取れる範囲で作る。**どれかを既定として勝手に進めない。**
選択肢を挙げられないほど不明なら、その旨を書く。

### 3. ラベルを付けて次へ進む

```sh
gh issue edit <番号> --add-label needs-decision
```

ラベルは、ループが対象を選ぶときの除外条件になる。回答が来るまで同じIssueで空転しない。

そのIssueの作業ブランチは残す。`main` をクリーンな状態へ戻してから次のIssueへ移る。

### 4. 回答を読み取って再開する

回答コメントを読み、内容に従って作業を再開する。

```sh
gh issue edit <番号> --remove-label needs-decision
```

ラベルを外してから作業を始める。外し忘れると、次回も除外されたままになる。

**回答が選択肢のどれでもない、または質問に答えていない場合**は、再開せずステップ2へ戻り、
何が分からなかったかを具体的に書いて質問し直す。曖昧な回答を解釈で埋めない。

### 5. 決まったことを資料へ戻す

回答は、次に同じ判断が起きたときには資料であるべきものである。

| 回答の性質 | 戻す先 |
| --- | --- |
| その機能の受け入れ条件 | Issue本文の `## Acceptance criteria` |
| 横断的な設計契約 | `docs/` の該当文書 |
| 再利用される判断 | ADR（`adr-writing` Skill を適用する） |

Issueのコメントに残したままにしない。コメントは時系列の記録であり、
次に読む人が探す場所ではない。

## ラベルの準備

`needs-decision` ラベルが無いリポジトリでは、最初の1回だけ作成する。

```sh
gh label create needs-decision \
  --description "無人ループが人間の判断を待っている" \
  --color D93F0B
```

## やってはならないこと

- 回答を待って停止する。待つなら質問を残す意味が無い
- 選択肢のどれかを既定として進め、質問だけ形式的に残す
- 同じ内容の質問を複数のIssueへ重複して書く
- 資料に書かれている事柄を質問する（`decision-agent` を先に使う）

## 参照

- `decision-agent`: 質問する前に、資料から答えられるかを判定する
- `adr-writing`: 回答が再利用される判断だった場合に記録する
